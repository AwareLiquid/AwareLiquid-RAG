# EDGE_CASCADE — 端侧级联 + 云端回退（金融场景架构评估）

> 2026-09 · Owner: Everest · 状态：架构设想，未原型验证
>
> 问题：MT-LNN 架构做成端侧本地金融模型，不会的知识经路由送云端
> Transformer LLM + 高级 RAG（本仓库 = grounding 层），成本与效率能否提升？

## 1. 架构形态

```
金融查询
   │
   ▼
端侧 MT-LNN（常开，O(1) 状态，CPU）      ← 本地可答就本地答（零边际成本）
   │  没把握（路由信号）
   ▼
云端 Transformer LLM + AwareLiquid-RAG    ← 难查询 + 事实盲点
   │
   ▼
带来源标注的答案（金融场景：答案必须可溯源）
```

- **端侧层**：O(1) 恒定状态 + 常开——这是别人在端侧做不到的（KV 无膨胀）
- **路由**：已有原生件——SalienceEventDetector（意外点火）+
  DeliberationRouter（熵三路 + 因果一致性底线）→ cloud_client
- **云端层**：Transformer LLM + 本仓库的金融文档 QA 适配器
  （44/48 = 91.7%，五个金融文档领域，冻结基座 + API）+ Awareness KaaS

## 2. 成本模型（级联的核心公式）

```
端到端成本 = (1 − X) × C_cloud + X × C_local + C_router
质量       = 本地质量 × X + 云端质量 × (1 − X) − 路由误判损失
```

- X = 本地可答率（决定一切）
- C_local ≈ 0（边际成本）；C_cloud = 模型单价 + RAG token 成本
- 业界参照（FrugalGPT 等）：级联在质量持平下省 50–98% 成本
- **RAG 的 token 账要算对**：朴素 RAG 每查询塞大量上下文 = 省不了；
  渐进式披露 + Context Pack + 零 LLM 检索（Awareness 已有）才是省钱路径

## 3. 现有资产映射（金融场景）

| 层 | 资产 | 状态 |
|---|---|---|
| 端侧模型 | 1.1B 适配器（聊天级）/ 2B 训练中 | ⚠️ **金融级端侧模型还不存在**（需金融语料 + 领域评测） |
| 路由 | SalienceEventDetector + DeliberationRouter（M1 `mt_lnn/`） | 研究级，**路由准确率未测** |
| 云端 | 本仓库金融文档 QA 适配器（91.7%） | ✅ 已实测（回归基线） |
| 知识 | Awareness KaaS（公域知识，ERC-8350 锚定） | 基础设施在 |
| 因子/拟合 | 连续时间核 × 不规则金融时序 | 独立数值线（非 LLM），NASA 电池/事件流实证支持 |

## 4. 三个必须补的数字（优先级排序）

1. **路由准确率**：误判率（该升的不升 = 质量风险；该本地化的升了 = 白花钱）
   —— 级联的全部收益取决于它，而它从未被测量
2. **本地可答率 X**：金融查询有多少比例能被端侧模型可靠承接
3. **端到端成本对比**：级联 vs 纯云端，同质量口径下的真实节省比例

## 5. 坑（诚实清单）

- 金融答案**必须可溯源**——本地模型的错误答案被路由漏过 = 责任事故；
  云端 + grounding 必须是质量底线
- 别把"因子/拟合"混进 LLM 线：因子是数值模型，连续时间核在
  不规则金融时序（tick/高频）上是真优势，但那是另一条产品线
- 级联的赢面在 X 大且路由准；X 小或路由烂时，级联是负资产

## 6. 最小验证路径

1. 用 1.1B 适配器 + Awareness Cloud + 本仓库适配器搭最小原型
2. 测 §4 三个数字（几十条金融查询即可出方向性结论）
3. 数字出来前，不做任何生产承诺

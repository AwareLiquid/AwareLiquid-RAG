# AFAC Qwen 金融长文本 QA：研究与实现交接文档

> 文档版本：2026-07-18  
> 适用范围：AFAC「金融长文本 Agent 的动态记忆压缩与高效问答」赛事方案  
> 交接目标：让下一位开发者可以在当前仓库上继续实现合规、高准确率、可验证的 Qwen API 答题系统。

## 0. 一页结论

本项目的正式比赛主线已经冻结为：

```text
问题分类
→ 规则/结构化词法检索
→ 证据覆盖与缺口补检
→ 保留完整证据窗口、表格行、脚注和来源
→ 本地安全计算/候选选项验证
→ Qwen 生成最终答案
→ 格式、数值和证据一致性校验
```

核心判断：比赛的主要瓶颈不是训练新的液态神经网络，而是让冻结的 Qwen 能够稳定拿到正确、完整、位置合理的金融证据。

液态神经网络、Embedding、Rerank、RAPTOR、GraphRAG 等暂不进入正式答题主链路。液态神经网络只保留为后续研究方向；Embedding/Rerank 及微调方案在当前赛事约束下不作为实现前提。

优先级从高到低：

1. [赛事精简规则](<../output/pdf/AFAC-赛题四-Markdown/金融长文本 Agent 的动态记忆压缩与高效问答-精简版.md>)

已确认的赛事约束：

| 事项 | 结论 |
|---|---|
| 基座模型 | 仅使用 Qwen 系列，通过官方 API 调用 |
| 微调 | 不做微调 |
| reasoning | 不开启 Qwen reasoning/思考模式；不依赖显式 CoT 输出 |
| Embedding | 禁止作为正式方案依赖 |
| Rerank | 禁止作为正式方案依赖 |
| Token 预算 | 全部接口调用总和不超过 500 万 Token |
| 评分 | 准确率权重 70%，Token 效率权重 30% |
| A 榜 | 提供 `doc_ids`，可以离线深度预处理 |
| B 榜 | 不提供 `doc_ids`，需要自行定位候选文档 |
| 本地预处理 | 不消耗 API Token，应尽量在离线阶段完成 |

当前阶段的默认模型策略：先以赛事材料中使用的 `qwen-plus` 作为基准，优先优化证据链路、问题路由和验证器；在这些模块稳定前，不切换模型作为主要实验变量。

## 2. 当前仓库状态

### 2.1 可以复用的部分

- [`awareliquid/memory/knowledge_store.py`](../awareliquid/memory/knowledge_store.py)：SQLite 存储和 FTS5/BM25 词法检索，可以作为正式方案的基础。
- [`awareliquid/adapter/qwen_client.py`](../awareliquid/adapter/qwen_client.py)：冻结 Qwen API 适配和 Token 用量统计。
- [`awareliquid/adapter/qa_agent.py`](../awareliquid/adapter/qa_agent.py)：已经具备 `doc_ids` 过滤、选项输入和基础答题编排。
- [`README.md`](../README.md) 与 [`docs/ARCHITECTURE.md`](./ARCHITECTURE.md)：明确了外部记忆适配器和 Qwen API 的整体边界。

### 2.2 正式比赛前必须调整的部分

1. [`awareliquid/memory/encoder.py`](../awareliquid/memory/encoder.py) 默认使用 `intfloat/multilingual-e5-small`，正式比赛路线必须关闭或隔离 dense embedding 路径。
2. [`awareliquid/adapter/qa_agent.py`](../awareliquid/adapter/qa_agent.py) 当前主要是 dense + BM25 的 RRF 混合和单轮检索，需要改成词法/结构化检索和多阶段证据补检。
3. [`awareliquid/adapter/compressor.py`](../awareliquid/adapter/compressor.py) 采用句子级有损压缩，可能删除“除外、但是、截至、同比口径、脚注”等决定答案的条件。正式方案应改为证据窗口、完整表格行和来源保留。
4. 当前缺少金融表格对象、指标/年份/单位解析、受限计算器、候选答案验证器和证据充分性判定。

### 2.3 当前系统的真实定位

当前仓库是一个可工作的研究原型，不是已经完全符合赛事规则的最终提交系统。下一位开发者不应先做模型训练，而应先完成“合规词法检索 + 结构化证据 + 可验证答题”的闭环。

## 3. 论文依据与可吸收机制

时间均为 arXiv 首次提交时间；可靠性用于区分“已通过会议/期刊评审”和“最新但尚未充分验证”的工作，不代表论文指标可以直接迁移到本赛事。

### 3.1 主线论文

| 优先级 | 论文 | 时间与状态 | 应吸收的机制 | 适配度 |
|---|---|---|---|---|
| P0 | [FinQA](https://arxiv.org/abs/2109.00122) | 2021-09-01；EMNLP 2021 | 金融数值推理、可解释计算程序、文本与表格联合证据 | 高 |
| P0 | [Fine-grained Retriever for FinQA](https://arxiv.org/abs/2206.08506) | 2022-06-17；FinQA 竞赛系统论文 | 不只取整段文本，还要定位相关行和单元格 | 高 |
| P0 | [Chain-of-Table](https://arxiv.org/abs/2401.04398) | 2024-01-09；ICLR 2024 | 让表格作为中间状态逐步演化，而不是用自然语言硬算 | 高 |
| P0 | [ECoRAG](https://arxiv.org/abs/2506.05167) | 2025-06-05；有公开代码的预印本 | 根据证据充分性进行压缩，不足时继续检索 | 高 |
| P0 | [RI²VER](https://arxiv.org/abs/2506.00425) | 2025-05-31；ACL 2025 Findings | 为每个候选答案独立收集并验证跨段证据 | 高 |
| P0 | [FinLongDocQA / FinLongDocAgent](https://arxiv.org/abs/2604.03664) | 2026-04-04；最新预印本 | 长财报、多表、跨表、多轮检索、中间计算和结果验证 | 极高，但需自行验证 |
| P0 | [PAR²-RAG](https://arxiv.org/abs/2603.29085) | 2026-03-30；最新预印本 | 先做高召回 Coverage，再做有证据充分性控制的 Commitment | 高，但需自行验证 |
| P1 | [Program of Thoughts](https://arxiv.org/abs/2211.12588) | 2022-11-22；TMLR 2023 | 将计算交给外部程序，降低模型心算错误 | 高 |
| P1 | [Adaptive-RAG](https://arxiv.org/abs/2403.14403) | 2024-03-21；NAACL 2024 | 根据问题复杂度选择无检索、单轮检索或多轮检索 | 高 |
| P1 | [Question Decomposition for RAG](https://arxiv.org/abs/2507.00355) | 2025-07-01；ACL SRW 2025 | 将多跳问题拆成子问题分别取证 | 高；去掉论文中的 rerank |
| P1 | [Never Lost in the Middle](https://arxiv.org/abs/2311.09198) | 2023-11-15；ACL 2024 | 训练结论不能直接使用，但可借鉴证据分解和上下文组织 | 中高 |
| P1 | [Lost in the Middle, and In-Between](https://arxiv.org/abs/2412.10079) | 2024-12-13；预印本 | 多跳证据之间的距离也会影响模型使用效果 | 中高 |

### 3.2 研究和评测参考

- [BRIGHT](https://arxiv.org/abs/2407.12883)：2024-07-16 首次提交，2025-03-26 更新。它说明需要推理才能找到相关文档的检索任务很难，适合借鉴评测方法，不是直接实现方案。
- [ReAct](https://arxiv.org/abs/2210.03629)：2022-10-06，ICLR 2023。可借鉴工具调用循环，但正式方案应改成确定性的有限状态机，不能依赖自由形式 reasoning。
- [RAPTOR](https://arxiv.org/abs/2401.18059)：2024-01-31，ICLR 2024。创新是层次化摘要树，但依赖 Embedding、聚类和摘要，和正式规则冲突。
- [GraphRAG](https://arxiv.org/abs/2404.16130)：2024-04-24，预印本。可借鉴文档引用关系，但不建议当前阶段构建 LLM 生成的知识图谱和社区摘要。
- [M3DocRAG](https://arxiv.org/abs/2411.04952)：2024-11-07，预印本。适合图表/视觉证据研究，但多模态检索器不进入当前正式主链路。
- [STEC](https://arxiv.org/abs/2607.10795)：2026-07-12，刚提交的预印本。提出“按候选答案聚合证据再验证”，创新性强，但太新，只作为实验候选。
- [Agentic Financial RAG](https://arxiv.org/abs/2605.05409)：2026-05-06，但已撤回，作者指出实验方法存在根本性错误，不采信其指标。

## 4. 冻结后的目标架构

### 4.1 离线阶段：零 API Token

对每个 PDF/文档建立以下结构：

- `doc_id`
- 页码、章节、标题、段落位置
- 条款编号和法条/章节引用
- 表格标题、表头、行名、列名、单位、脚注
- 财务指标、年份、日期、百分比、货币、数值归一化形式
- 原始文本和邻近文本窗口
- 文档内引用关系和相邻证据关系

建立的索引只使用合规的本地方法：

- FTS5/BM25
- 标题/章节索引
- 数字、年份、日期、单位索引
- 正则匹配
- 表格行列索引
- 页码和邻近窗口索引

### 4.2 在线阶段：按问题复杂度路由

问题先进入确定性路由器：

| 类型 | 处理方式 |
|---|---|
| 事实题 | 关键词、章节、精确匹配、邻近证据窗口 |
| 条款/例外题 | 条款编号、否定词、例外词、完整上下文 |
| 公式/计算题 | 指标和年份定位，交给本地受限计算器 |
| 比较题 | 每个目标分别取证，再进行统一比较 |
| 多跳题 | 先高召回，再根据证据缺口补检 |
| 选择题 | 对每个选项分别收集支持/反驳证据 |

### 4.3 证据循环

```text
第一轮：问题/选项/目标词法召回
→ 检查是否覆盖每个文档、年份、指标和表格
→ 补充章节、相邻段、完整表格行、脚注和例外条件
→ 判断证据是否足够
→ 不足则针对缺口继续检索
→ 组装少量但完整的证据块
→ 调用 Qwen
→ 校验答案、选项、数字和格式
```

上下文组装原则：

- 原始证据优先于摘要；
- 证据块内保留前后文；
- 关键证据放在上下文开头或结尾；
- 相关的多个证据尽量相邻；
- 表格问题尽量保留完整相关行/列，而不是切成孤立句子；
- 每块证据保留 `doc_id/page/section/table/row` 来源信息。

## 5. 实施路线图

### P0：先完成正式合规闭环

1. 增加正式配置，关闭 dense embedding 和所有 rerank 入口。
2. 保留并强化 FTS5/BM25，加入标题、章节、数字、年份和单位索引。
3. 设计统一的 `Evidence` 数据结构，必须携带原文和来源位置。
4. 重写压缩器为“证据窗口组装器”，避免无依据删除句子。
5. 增加问题类型路由器。
6. 增加金融表格和数值解析。
7. 增加安全的本地计算器：只允许白名单运算，不执行 Qwen 任意代码。
8. 增加选项级支持/反驳证据验证。
9. 增加 Token 统计、停止条件和最终格式校验。

### P1：提高复杂题准确率

1. 实现 PAR²-RAG 风格的“覆盖 → 深挖”两阶段检索。
2. 实现 ECoRAG 风格的证据充分性检查。
3. 对比较题和多跳题实现逐文档提取、再统一比较。
4. A 榜利用已知 `doc_ids` 做深度离线预处理。
5. B 榜增加候选文档定位阶段，但继续使用词法和结构方法。

### P2：评测和可选研究

1. 建立按题型拆分的离线评测集。
2. 对比单轮检索、多轮检索、证据窗口和候选验证的增益。
3. 评估 `STEC` 的候选答案证据聚合思想。
4. 只有在正式主链路稳定后，才研究液态神经网络或其他小模型。

## 6. 必须做的消融实验

至少保留以下实验组：

| 实验组 | 检索 | 结构化证据 | 多轮补检 | 本地计算 | 选项验证 |
|---|---|---|---|---|---|
| Baseline | 当前实现 | 否 | 否 | 否 | 否 |
| E1 | BM25/FTS5 | 否 | 否 | 否 | 否 |
| E2 | BM25/FTS5 | 是 | 否 | 否 | 否 |
| E3 | BM25/FTS5 | 是 | 是 | 否 | 否 |
| E4 | BM25/FTS5 | 是 | 是 | 是 | 否 |
| E5 | BM25/FTS5 | 是 | 是 | 是 | 是 |

每组至少记录：

- 总准确率；
- 事实题、计算题、比较题、多跳题准确率；
- 表格数值执行准确率；
- 证据覆盖率；
- 单题及总 Token；
- 错误类型：漏检、错表、单位错、年份错、例外条件丢失、计算错、选项判断错。

## 7. 验收标准

正式提交前应满足：

- 默认运行路径不加载 Embedding 模型；
- 默认运行路径不调用 Rerank 模型；
- 默认不启用 Qwen reasoning/思考模式；
- 每个答案都能追溯到证据块和来源位置；
- 计算题由本地白名单计算器复核；
- 选择题经过候选选项级验证；
- A 榜严格使用给定 `doc_ids`；
- B 榜具备独立的候选文档定位流程；
- API Token 统计准确且可复现；
- 输出格式可以直接生成赛事要求的提交文件。

## 8. 明确不做的事情

- 不把液态神经网络作为当前比赛主链路；
- 不训练本地 Embedding/Rerank 模型；
- 不使用 RAPTOR 的 Embedding + 聚类 + 摘要树作为正式实现；
- 不使用 GraphRAG 的 LLM 知识图谱/社区摘要作为第一阶段方案；
- 不让 Qwen 直接执行任意 Python 代码；
- 不为了节省 Token 删除未经验证的金融原文、脚注、单位和例外条件；
- 不在证据链路未稳定前通过更换 Qwen 模型掩盖检索问题。

## 9. 下一位开发者的第一步

按以下顺序开始，不要从液态神经网络训练开始：

1. 运行当前测试，记录当前 Baseline。
2. 增加“正式合规模式”，关闭 dense embedding。
3. 实现 `Evidence` 结构和原文窗口组装。
4. 实现题型路由和 BM25/FTS5 结构化召回。
5. 加入表格/数值解析与本地安全计算。
6. 加入选项级验证。
7. 最后实现多轮证据补检和证据充分性停止条件。

完成上述 P0 后，再讨论是否需要引入任何新的模型或液态神经网络实验。
